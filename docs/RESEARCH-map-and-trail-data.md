## ① 카카오맵 API — 필요한 지도 기능이 가능한가

### 제공 현황 ✅

| 구분 | 내용 |
|---|---|
| 지도 SDK | **Web(JavaScript) · Android v2 · iOS v2** 세 플랫폼 |
| 구 SDK | Android/iOS v1 은 **2024-06-30 지원 종료** (2024-09 부터 인증 오류). v2 필수 |
| REST API | 주소/좌표 변환, 장소 검색, 경로 조회, 정적 지도 |
| 신규 4종 (2026-07-21) | 대중교통 경로 · **도보 경로** · 자전거 경로 · 정적 지도 조회 |

### 쿼터 · 과금 (2026-07-21 변경) ✅

- 개발자 계정당 **첫 번째로 활성화한 앱에만** 무료 쿼터 제공
- 두 번째 앱부터 또는 초과 사용 시 **비즈월렛 연결 + 사용량 과금**
- 신규 4종: 일 1,000건 무료 → 초과 시 경로 API **건당 10원**, 정적 지도 **건당 2원**
- 기존 Map/Local API 는 기존 제공량 유지
- `[앱] > [제품 설정] > [카카오맵] > [사용 설정]` 으로 심사 없이 이용 가능

### 우리 프로젝트 요구사항 대비 판정

| 필요 기능 | 카카오맵 | 판정 |
|---|---|---|
| 모바일 · 웹에서 지도 표시 | Android v2 / iOS v2 / JS SDK | ✅ 가능 |
| 현재 위치 표시 | SDK 마커 · 라벨 | ✅ 가능 |
| 산행 경로(트랙) 폴리라인 표시 | SDK 에 라벨 · 다각형 · 오버레이 제공 | ✅ 가능 (폴리라인 세부 API 는 ❓) |
| **등산로 노선 데이터 제공** | 제공하지 않음 | ❌ **별도 조달 필요** |
| 등산로 경로 안내(내비) | 신규 도보 경로 API 는 도심 보행자 대상. 산길 커버리지 ❓ | ❌ 기대하지 않는 편이 안전 |
| 지형도 · 등고선 레이어 | 공식 문서에 언급 없음 | ❓ 확인 필요 |
| **오프라인 지도** | 문서에 오프라인 지원 언급 **없음** | ❌ **미지원** |
| API 응답 저장 · 캐싱 | 실시간 호출만 허용, 결과 저장 불가 (장소ID·장소명·place_url 만 예외) | ⚠️ **정책상 제한** |

### 결론 — ① 에 대한 답

**"지도를 보여주고 그 위에 내 위치와 경로를 그리는" 용도로는 충분하다.** 세 플랫폼 SDK 가 모두 있고 오버레이도 제공한다.

다만 두 가지는 카카오맵으로 해결되지 않는다.

1. **등산로 노선 데이터의 공급원이 아니다.** 카카오맵은 배경지도이고, 어느 산의 어떤 코스가 어떤 좌표를 따라가는지는 제공하지 않는다. → ② 에서 별도 조달.
2. **산에서의 오프라인 동작을 충족하지 못한다.** 오프라인 타일 지원이 문서에 없고, 응답 데이터 캐싱이 정책상 제한된다. 모바일 Primary + 신호 없는 산이라는 전제와 정면으로 충돌한다.

> ⚠️ 캐싱 제한 조항은 **공식 문서에 명시되어 있지 않고** 카카오 담당자가 데브톡에서 반복 답변한 내용이다. 실제 서비스 전에 **공식 문의로 확인해야 한다.** 특히 "지도 타일 캐싱" 과 "Local API 응답 저장" 은 별개 사안일 수 있다.

### 그래서 중요한 설계 분리

```
지도 타일        온라인 전용. 교체 가능한 레이어로 취급한다
                 (카카오맵 / V-World / 국토지리정보원 중 선택)

등산로 노선 · 지점 · 고도    우리 데이터. 공공데이터에서 확보해 우리 DB 에 보관
                            → 오프라인에서도 "타일 없이 선만 그리기" 폴백 가능
```

이 분리를 지키면 **지도 제공자를 나중에 바꿔도 앱의 핵심 기능이 흔들리지 않는다.**
지도 SDK 최종 선택은 모바일 기술 스택 결정(E-4)과 함께 하는 것이 맞다.

## ② 등산로 데이터 — 공공 API / 데이터

### 후보 목록

#### 1. 전국등산로표준데이터 — 산림청 ★ 1순위 ✅

```
공공데이터포털  data.go.kr/data/15029184/standard.do
형식            SHP · JSON · GPX
건수            2,919행
갱신            수시
비용            무료
이용허락범위    제한 없음
포함 항목       위치 · 노선 · 거리 · 소요시간 · 난이도 ·
                주변 편의시설 · 접근성
```

**우리 `Course` 모델과 필드가 상당히 겹친다** — 거리 · 소요시간 · 난이도가 원본에 이미 있다.
"이용허락범위 제한 없음" 이므로 우리 DB 에 저장 · 가공할 수 있다.

#### 2. 산림청 등산로정보 (직접 다운로드) ✅

```
forest.go.kr  정보공개 > 공공데이터 개방 > 등산로정보
형식          GPX · SHP · JSON
단위          산별 개별 다운로드 (전국 일괄 옵션 ❓)
문의          산림빅데이터팀 042-481-8809
```

주의사항으로 명시된 것:
- **등산로 통제 · 폐쇄 여부, 추천구간 정보는 실시간 반영되지 않는다** → 소관 지자체 문의 안내
- 국립공원 탐방로는 이용 가능 구간을 별도 확인 필요
- 데이터 위 · 변조 금지

→ 안전 관련 기능(통제 구간 안내)에 이 데이터를 그대로 쓸 수 없다는 뜻이다.

#### 3. 국립공원공단 ✅

| 데이터 | 내용 |
|---|---|
| 국립공원 선형시설 (`15091972`) | 전국 국립공원의 탐방로 · 진입도로 위치정보 |
| 국립공원 탐방로 공간데이터 | 별도 제공 |

다목적위치표지판은 **지점 + 고도**가 함께 있어 지점 데이터와 고도 보정에 유용하다.

#### 4. 산 마스터 데이터 ✅

| 산림청 산정보 서비스 (`15058662`) | 국내 3,368개 산 설명 |

#### 5. 배경지도 · 공간정보 플랫폼 ✅

| 출처 | 내용 |
|---|---|
| **V-World (브이월드)** | 국가공간정보 2D/3D 오픈API. 배경지도 제공. **체육 카테고리에 등산로 포함** (자연공원 · 산책로 · 자전거길 등과 함께). 인증키 신청 필요 |
| **국토지리정보원 국토정보플랫폼** | 배경지도 오픈API (**WMTS**) — 일반 · 영상 · 위성 · 백지도 · 야간 · 하이브리드 등. 검색 API(POI · 지명 · 기준점 · 지오코더) |

카카오맵 대안으로 검토할 가치가 있다 — 특히 **WMTS 는 표준 프로토콜**이라 오프라인 타일 전략을 세우기 쉽다 (단, 각 플랫폼의 약관 확인 필요 ❓).

#### 6. 고도(Elevation) 데이터 ✅

| 출처 | 내용 |
|---|---|
| 국토지리정보원 DEM (`15059920`) | 수치표고모델 파일 데이터 |
| 수치표고모델 90M (국가공간정보포털) | 저해상도 광역 |
| GPX 파일의 `<ele>` | 등산로 GPX 에 고도가 들어있을 가능성 ❓ — 파일을 받아 확인해야 한다 |

우리 `Course.elevation: number[]` 을 채울 수 있는 경로가 세 가지 있다.

### 아직 조사하지 않은 것

- **OpenStreetMap** (`highway=path` · `sac_scale` 등) — 국내 등산로 커버리지와 ODbL 라이선스 영향 미조사
- 두루누비(한국관광공사 걷기여행길) — 둘레길 중심이라 등산로와 성격이 다를 수 있음
- 지자체 개별 등산로 데이터

## ③ Course 모델 결합 제안

### 현재 모델의 문제

```ts
// packages/core/src/types.ts
interface Course {
  id, name, region, distance, duration, ascent, level, calories,
  image, tags, surface, water, highlights, risks, elevation: number[]
}
```

- **산과 코스가 한 덩어리다.** `region` 이 문자열이고 산 자체가 엔티티가 아니다
- **노선 형상(좌표)이 없다.** `elevation` 배열만 있고 실제 경로 좌표가 없다
- **지점(waypoint) 이 없다.** `highlights` 가 자유 텍스트다 (ISSUE-014 에서 이미 지적)
- 하드코딩 10개 (`catalog/courses.ts`)

### 제안 — 4계층으로 분리

```
Mountain          산 마스터
  ← 100대명산 목록정보 · 산정보 서비스
  id · name · region · lat · lng · peakAltitude · sourceMountainCode

Trail             등산로 노선  (현재 Course 의 후신)
  ← 전국등산로표준데이터 · 산림청 GPX/SHP
  id · mountainId · name
  distance · estimatedDuration · sourceDifficulty
  geometry: GeoJSON LineString        ← 신설. 실제 경로 좌표
  facilities · accessibility          ← 원본의 주변 편의시설 · 접근성
  source · sourceId · fetchedAt       ← 출처 추적

Waypoint          경로 상의 지점
  ← GPX waypoint · 국립공원 다목적위치표지판
  id · trailId · name · cumulativeDistance · altitude · kind
  ⏸ ISSUE-014 의 "목표 지점" 후보 데이터가 된다.
     목표 지점 구조는 미결정이므로 이 계층의 스키마도 지금 확정하지 않는다

ElevationProfile  고도 프로파일
  ← GPX <ele> 또는 DEM 샘플링
  trailId · samples: { distance, altitude }[]
  → 현재 Course.elevation: number[] 를 대체
```

### 필드 매핑 — 우리 모델 ← 공공데이터

| 우리 필드 | 출처 | 비고 |
|---|---|---|
| `name` · `region` | 등산로표준데이터 · 산 마스터 | |
| `distance` | 등산로표준데이터 **거리** | 단위 확인 필요 ❓ |
| `duration` | 등산로표준데이터 **소요시간** | 단위 확인 필요 — **ISSUE-001**(분/초 혼용)과 함께 정리 |
| `level` | 등산로표준데이터 **난이도** | 원본 난이도 체계가 우리 1~4 와 다를 수 있음 → **매핑 테이블 필요** ❓ |
| `ascent` | **원본에 없으면 고도 프로파일에서 계산** | 누적 상승량 산출 로직 필요 |
| `elevation[]` | GPX `<ele>` 또는 DEM 샘플링 | ❓ |
| `geometry` | GPX/SHP 노선 | **신설** |
| `surface` · `water` | 원본에 대응 항목 없음 | 자체 콘텐츠 또는 파생 |
| `highlights` | Waypoint 로 대체 | ⏸ 미결정 |
| `risks` | 원본에 대응 항목 없음 + 통제/폐쇄는 실시간 아님 | **자체 콘텐츠 + 면책 표기 필요** |
| `calories` | 공공데이터에 없음 | 우리가 계산 (체중 · 거리 · 고도) |
| `image` | 공공데이터에 없음 | 자체 확보 |
| `tags` | 파생 | |

### 데이터 소유 · 흐름

```
공공데이터 (일괄 다운로드 · 주기적 갱신)
        ↓  좌표계 변환 · 정규화 · 난이도 매핑 · 고도 보강
      우리 서버 DB          ← 여기가 코스 데이터의 원본(source of truth)
        ↓  API
  모바일 앱 (로컬 캐시 · 오프라인)  /  웹
        +
  지도 타일  ← 카카오맵 / V-World / 국토지리정보원 (온라인 전용, 교체 가능)
```

**핵심:** 공공데이터는 저장 · 가공이 허용되므로(전국등산로표준데이터는 "이용허락범위 제한 없음") **노선 데이터는 우리 것으로 만들 수 있다.** 지도 타일만 온라인 의존으로 남는다. 이 구조에서는 신호가 없어도 배경 없이 경로와 내 위치를 그릴 수 있다.

### core 코드에 미치는 영향

- `packages/core/src/catalog/courses.ts` 하드코딩 10개 → **시드/폴백으로 격하**, 실데이터는 서버에서
- `Course` 타입 → `Mountain` / `Trail` / `Waypoint` / `ElevationProfile` 로 분해
- `findCourse()` · `recommendNext({ courses })` 의 주입 구조는 그대로 쓸 수 있다 (이미 코스를 인자로 받는다)
- `charts.trailGeometry()` 의 고정 경로(ISSUE-018)를 실제 `geometry` 로 교체

**전부 스키마 변경이므로 보류 대상이다.** ISSUE-001 · 003 · 011 · 014 와 **한 번에** 처리한다.

## ④ 연동 전에 확인해야 할 것

| # | 확인 사항 | 방법 |
|---|---|---|
| 1 | 전국등산로표준데이터의 **실제 필드명 · 난이도 체계 · 좌표계** | 파일 1건 다운로드해 확인. 국내 공간정보는 EPSG:5179 등을 쓰는 경우가 많아 **WGS84 변환이 필요할 수 있다** ❓ |
| 2 | GPX 에 고도(`<ele>`)가 포함되는지 | 파일 확인 |
| 3 | 노선 데이터의 **좌표 밀도** (경로를 그릴 만큼 촘촘한가) | 파일 확인 |
| 4 | **카카오맵 캐싱 · 오프라인 정책의 공식 입장** | 카카오 공식 문의 |
| 5 | V-World · 국토지리정보원 배경지도의 **캐싱 · 오프라인 약관** | 각 플랫폼 약관 확인 |
| 6 | 통제 · 폐쇄 구간 정보를 어디서 받을 것인가 | 실시간 아님 → 안전 기능 설계 시 재검토 |
| 7 | 지도 SDK 최종 선택 | **모바일 기술 스택 결정(E-4)과 함께** |
